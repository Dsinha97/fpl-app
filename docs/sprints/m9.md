# M9 — Design Audit

An external design audit of every screen, worked in four sprints: **A** built primitives, **B**
applied them app-wide, **C1** did the per-screen visual work, **C2** the items that were product
work wearing design clothes. Linear: [DSI-134](https://linear.app/dsinha-org/issue/DSI-134)
(A), [DSI-135](https://linear.app/dsinha-org/issue/DSI-135) (B),
[DSI-138](https://linear.app/dsinha-org/issue/DSI-138) (B, segmented control),
[DSI-136](https://linear.app/dsinha-org/issue/DSI-136) (C1),
[DSI-137](https://linear.app/dsinha-org/issue/DSI-137) (C2), plus the per-screen audit issues
DSI-118 to DSI-129 and two found in flight, DSI-139 and DSI-140.

## What the audit was right about, and what it wasn't

Roughly half of each audit item was already fixed, already false, or would have been a regression
if applied literally. That is worth recording, because the pattern repeated in every sprint and it
is the reason each item below carries a measurement rather than a verdict.

Three examples of the audit being wrong in a way that mattered:

- **"Desaturate the FDR matrix."** Measured first (Machado 2009, severity 1.0, linear-RGB
  separation): the difficulty ramp holds ≥ 0.32 between adjacent steps under all three CVD
  conditions, sometimes wider than at normal vision. It was the *venue* channel that was broken —
  green ring for home against red for away, which scores 1.039 at normal vision and 0.204 under
  deuteranopia. Desaturating would have discarded a working channel to fix a broken one.
- **"Make the deadline a tab bar."** Measured the widths; it did not fit, and the owner agreed
  once shown.
- **"88 `title=` attributes need converting."** Measured: 14 exceed 40 characters, and most of
  those are truncation fallbacks where `title` is the correct idiom. Four carried reasoning
  available nowhere else.

## Sprint C2 — feature-shaped (DSI-137)

- **"My squad only" on `/news`** — the page held no squad state at all. Matching is by player
  *code*: `change_feed.player_code` and `news_feed`'s player entity ids are codes, a draft stores
  element ids, and one id-scoped query bridges them. Feed 200 rows → 5, headlines 145 → 17.
- **Player panel actions on `/deadline`** — Set C / Set VC write to the draft. Remove is not
  offered: on that page the squad is the real team before a deadline, and a removal with no
  replacement is not a move FPL allows.
- **Apply to plan** on the chip recommendation, and `source: "manual"` now means a decision while
  a bare pin icon means a shortlist.
- **Import helpers** — clipboard paste plus a drawn schematic of the DevTools Network panel.
  Drawn, not screenshotted: a screenshot of Chrome is someone else's UI frozen at one version.
- **BGW/DGW on a fixture move** — a cross-round move reports the blank or double it creates.

## Found in flight

- **DSI-139** — `draft_snapshots` cloud sync failed silently: the upsert hit a missing UPDATE
  policy. Fixed with `ignoreDuplicates`, which is correct here because a snapshot is immutable.
  **Half open:** the failure is still console-only, with no user-visible surface.
- **DSI-140** — long methodology explainers rendered inline. Collapsed behind `NoteDisclosure`,
  lifted from the one `transfer-plan.tsx` had already invented.

## Tooling this sprint had to build

- **A signed-in test account.** Every signed-in verification before this was the owner signing in
  by hand, and `CLAUDE.md` recorded the lesson three times with no mechanism behind it. There is
  now a seeded fixture user and a `/signed-in` skill. It immediately found DSI-139, a bug
  invisible to every prior pass.
- **Scripted `Screens/` captures** (`scripts/capture-screens.mjs`, Playwright). The Browser pane
  cannot write files, so the reference frames had been hand-shot.

## Lessons worth keeping

- **A stale explainer is the default outcome, not an accident.** The venue encoding changed and
  its description went stale in three separate places — a matrix caption, five popups sharing one
  component, and (previously, recorded in `app/players/page.tsx`) a column legend. Encoding and
  prose live in different files; nothing links them but habit.
- **Two implementations of one thing means the fix lands once and is missed once.** The percentile
  bar, the `signed()` formatter (eight copies, three behaviours), the note disclosure.
- **Verify against the running app, not the diff.** A blank capture looked exactly like a broken
  conversion; the dev server had been stopped an hour earlier. Separately, programmatic
  `window.scrollTo` in the preview browser dispatches no scroll event, so a scroll-driven fix
  tested that way looks broken when it is not.

## Was open, now closed (DSI-141, 2026-09-13)

- **`/transfers`' 5 GW column — resolved.** The parked note rejected `--chart-1` for failing
  contrast on white (3.7:1). But light mode there is `purple-800`; `--chart-1` was never proposed
  for it, and light was never the complaint. Only the dark half borrowed the CTA accent. So light
  stays and dark moves to `--chart-1` — measured **11.21:1** against the ground it is actually
  painted on, rather than the 5.1:1 the note assumed against the card. DSI-124's top-quartile
  distinction survives and DSI-129's accent discipline holds; nothing was traded.
- **DSI-139's second half — done.** The snapshot push set no `error` at all, so the failure could
  not reach `SyncResult` even in principle; `watchAndSync` logged the rest to a console nobody had
  open. `lib/draft-sync.ts` now publishes the last outcome and `DraftSyncProvider` renders it.

## DSI-141 — six mobile defects, and two bugs testing found under them

Owner testing on a phone, after M9 had passed its own `responsive-check` matrix. Every one of the
six is the same shape: **a control that fits by scrolling or wrapping silently.** Nothing is
clipped, `document.body.scrollWidth` equals the viewport, and the options are unreachable anyway —
which is why a pass whose bar is "nothing overflows" kept certifying them.

- `SegmentedControl` scrolled with no affordance. Edge fades that appear only when a side has
  something hidden, plus the selected segment scrolled into view. One primitive, nine call sites.
- `/news`' "My squad only" moved beside the page title — it scopes the page.
- `/team`'s Telegram control became one icon plus an anchored panel, so four header actions fit one
  row. Its asset arrived as `public/telegram-logo.svg` and was a `.tsx` module: neither fetchable as
  an image nor compiled as code. Now `components/icons/telegram.tsx`.
- Rivals' two tables took the `DataTable` shell; the career half's six columns had been scrolling
  the whole document. Its "First season" row also spanned four columns of five.
- `/builder`'s squad select capped to the rename field's width, so Save stays on the row.
- `/players`' frozen column capped below `sm`, and `RoleBadges` draws the top duty plus `+N`.
- `/fixtures`' FDR filters moved behind the existing `FilterDisclosure`, each non-default choice
  still named outside it.

**Two bugs that only running it could find**, both under the `+N` chip:

- It nested a `<button>` inside `/builder`'s own row button — invalid HTML and a hydration error.
  The chip is a plain titled span unless the caller opts in with `revealable`.
- `TapToReveal`'s panel is `fixed z-30`, and was still painted over by the *next row's* `sticky
  z-10` cell: `fixed` positions against the viewport but does not escape a stacking context, and
  equal z-indexes are decided by DOM order. It portals to the body now.

**Two defects only the signed-in pass could see**, once the test account was available:

- The career rivals table was *still* widening the document after being given a scroll
  container — its grid item kept `min-width: auto` below `lg`, so the wrapper's overflow rule had
  nothing to engage against (529 → 593 on switching to Career; 375 = 375 after). The same
  ancestor-chain lesson DSI-138 wrote down for `SegmentedControl`, missed a second time, now in
  `CLAUDE.md`.
- The selected segment never scrolled into view on a hidden document: no rAF callbacks means
  `scrollTo({behavior:"smooth"})` is dropped entirely. `/settings`' Pipeline tab sat off screen at
  `scrollLeft 0`; the same call with `auto` landed. Instant when hidden or motion-reduced.

**One thing measured rather than fixed.** The owner reported the `/team` decisions lookback doing
nothing at 1 GW vs 3 GW. A `tsx` harness against entry 274486 says the window construction is
correct: only *scored* gameweeks count, and only GW3 has any, so every lookback sums the same
football. The defect was that an unchanged number explained nothing — it now states its own
coverage ("1 of 10 gameweeks in these lookback windows have been scored"). Renamed **Transfers
lookback**: it measures the past, and "horizon" is this app's word for a projection.
